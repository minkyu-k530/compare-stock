# Galaxy S24+ 화면 녹화 예비 측정

첫 기기는 **Galaxy S24+**, 촬영 방식은 **기기 자체 화면 녹화**로 고정한다. 이 문서의 4회는 촬영·판독 기준을 맞추는 **예비 시도**이며 [본 실험 60회 계획](EXPERIMENT_PLAN.md)의 결과에 합산하지 않는다. 2026-10-15 재촬영 기기는 ADB에서 Android `16`으로 확인했다. One UI **표시용 버전명**은 기기 설정 화면에서 아직 재확인하지 않았다. 실제 네 영상은 프레임별 PTS를 읽어 계산했으므로, 고정 FPS를 가정하지 않았다.

아래 4회 표는 **앞으로 같은 조건에서 촬영할 때의 절차**다. 실제 2026-10-15 재촬영은 삼성전자·키보드 닫힘 1페어와 SK하이닉스·키보드 열림 1페어였고, 두 페어 모두 한국투자→토스 순서였다. 따라서 네 시도를 동일 조건 2페어로 합산하거나 본 실험에 넣지 않는다. 판독 근거와 원본은 Git에서 제외된 로컬 `captures/pilot/retake-20261015-1619/`에 보관한다.

## 1. 짧은 녹화로 가능 여부 확인

1. **설정 → 유용한 기능 → 화면 캡처 및 화면 녹화**에서 **누른 위치 표시**를 켠다. 메뉴를 찾기 어렵다면 퀵패널의 화면 녹화 아이콘을 길게 눌러 설정을 연다. S24+는 삼성 내장 화면 녹화를 지원하며, 이 터치 표시 기능을 쓰는 데 개발자 옵션은 필수가 아니다. [삼성 화면 녹화 안내](https://www.samsung.com/ie/support/mobile-devices/how-to-record-your-screen-on-your-samsung-galaxy-device/), [삼성 녹화 설정 안내](https://www.samsung.com/us/support/answer/ANS10001616/)
2. 두 앱의 **종목 검색 결과 화면**에서 각각 5~10초짜리 영상을 하나씩 시험 촬영한다. 화면 녹화 시작 카운트다운이 끝난 뒤 검색 결과가 안정되면 탭한다. 녹화 파일에 **터치 점과 종목명·가격 숫자가 모두 보이는지** 확인한다. 녹화가 검게 나오거나 터치 점이 안 보이면 그 시도는 측정하지 않는다. 삼성은 일부 앱이 녹화를 제한할 수 있다고 안내한다. [삼성 녹화 설정 안내](https://www.samsung.com/us/support/answer/ANS10001616/)
3. 화면 주사율이 120Hz여도 녹화 영상이 120fps라는 뜻은 아니다. **프레임 속도를 추정해 입력하지 않는다.** 영상 파일의 각 프레임 표시 시각(PTS)을 판독하는 방식을 우선한다. [Android 프레임 속도 안내](https://developer.android.com/media/optimize/performance/frame-rate), [ffprobe 문서](https://ffmpeg.org/ffprobe.html)

개발자 옵션의 애니메이션 배율 등 체감 속도를 바꾸는 설정은 실험을 위해 조정하지 않는다. 녹화 옵션에서 누른 위치 표시를 제공하지 않을 때만 [Android 개발자 옵션의 Show taps](https://developer.android.com/studio/debug/dev-options)를 확인한다.

## 2. 예비 4회 실행

첫 질문은 **검색 결과에서 같은 종목을 탭한 때부터 선택 종목명과 그 종목의 0·빈칸·이전 종목 잔상이 아닌 가격 숫자가 동시에 읽히는 첫 프레임까지**다. 검색어 입력 시간은 포함하지 않는다. 두 앱에서 같은 종목을 미리 한 번 열고 검색 결과로 돌아온다. 검색어와 키보드 표시 여부도 고정한다. 각 시도 전 같은 검색 결과 화면이 안정된 뒤 3초 기다린다.

| 순서 | 앱 | 예비 `run_id` |
|---:|---|---|
| 1 | 토스 앱 · 증권 | `pilot-s24p-01a` |
| 2 | 한국투자 앱 | `pilot-s24p-01a` |
| 3 | 한국투자 앱 | `pilot-s24p-01b` |
| 4 | 토스 앱 · 증권 | `pilot-s24p-01b` |

각 시도를 **별도 원본 영상**으로 저장하고 파일명에 순서 번호를 붙인다. 앱 안의 계좌·잔고·알림·인증 정보가 보이는 화면은 촬영하지 않는다. 녹화 직후 영상을 재생해 터치 점과 완료 기준이 모두 확인되는지 검사한다. 실패한 시도도 삭제하지 말고 이유를 별도 메모에 남긴다. 영상 원본을 자르거나 재인코딩하지 않은 상태로 보관한다.

## 3. 프레임 판독과 서비스 입력

1. 터치 점이 **처음 나타난 영상 프레임**을 시작점으로, 선택 종목명과 그 종목의 가격이 동시에 읽히는 **최초 프레임**을 종료점으로 고른다. `0`·빈칸·이전 종목 가격의 잔상은 완료가 아니다. 각 경계의 바로 앞 프레임도 확인한다. 이 시작점은 실제 손가락 접촉이 아니라 **녹화에 표시된 터치 시점**이다.
2. 영상 편집기에서 각 경계 프레임의 PTS를 읽는다. Mac에서는 [전체 SOP](MAC_GALAXY_S24_PLUS_SOP.md)의 FFmpeg 이미지 추출과 `tools/measure_video_pts.py` 명령으로 프레임 번호·PTS·원본 SHA-256을 함께 검증할 수 있다. 두 PTS를 대시보드의 **프레임 표시 시각으로 계산**에 입력한다. 도구는 두 시각의 차이를 ms로 계산한다. 고정 FPS를 파일에서 확인한 경우에만 프레임 번호/FPS 계산을 쓴다. 브라우저 재생 위치만으로 찍은 값은 근사치로 표시한다.
3. [로컬 대시보드](http://127.0.0.1:8765/)에서 `capture_method=screen_recording`, `timing_basis=frame_timestamps`, `start_state=warm`, 같은 완료 기준·종목·기기·네트워크를 사용한다. 각 앱의 `run_order`는 위 표의 1~4다. 1·2회와 3·4회는 각각 같은 `run_id`로 저장한다. 한 페어의 첫 앱을 저장할 때 **저장 후 반대 앱 준비**, 두 번째 앱에서는 **기록 저장**을 누른다.
4. 앱 오류·재로그인이나 10초 제한 시간 초과는 완료 시간으로 바꾸지 않는다. `status=error` 또는 `timeout`으로 저장하고, 촬영 자체가 실패한 경우는 [시도 대장](EXPERIMENT_PLAN.md)에 `invalid_capture`로 남긴다.

예비 영상 4개로 두 앱에서 같은 시작·완료 기준을 읽을 수 있는지 먼저 판단한다. 가능하면 앱 버전·OS·촬영 설정을 고정하고 [본 실험 15블록](EXPERIMENT_PLAN.md)을 **별도 SQLite 파일**에서 시작한다. 예비 페어가 본 실험 통계에 섞이지 않도록 [SOP의 별도 DB·포트 절차](MAC_GALAXY_S24_PLUS_SOP.md)를 따른다. 이 영상만으로 앱의 내부 프로토콜이나 서버 처리시간을 판단하지 않는다.
